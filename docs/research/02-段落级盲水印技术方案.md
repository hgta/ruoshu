# 02 · 段落级盲水印技术方案（深度版）

> 目标：付费/VIP 章节被复制、转载、盗版后，能**定位到具体的泄露源账号**，
> 同时不损害正常读者的阅读体验。这是平台"版权保护"叙事的技术核心。

---

## 一、威胁模型：内容是怎么被偷走的

```
攻击路径          手段                    存活的内容形态     防御难度
─────────────────────────────────────────────────────────────────
P1 前端直接复制   右键/拖选/Ctrl+C          纯文本(带格式)     ★
P2 脚本批量抓取   curl/爬虫拿 HTML          纯文本             ★★
P3 截图/长截图    手机截屏、浏览器截图        图片               ★★★★
P4 OCR 识别       截图→OCR→文本             纯文本(有噪声)     ★★★★
P5 拍照/录屏      屏幕拍摄                  图片(透视畸变)     ★★★★★
P6 人工重打       盗版商雇人重新录入          纯文本(有改动)     ★★★★★
P7 读者账号被入侵 盗号者批量下载             纯文本             ★★★
─────────────────────────────────────────────────────────────────
```

**现实数据**（2025 上半年中国版权协会）：网文侵权链接 4700 万条，涉及 32000 个平台。
结论：**防是防不死的，必须"防 + 追溯"两手抓** —— 水印的价值不在于阻止，在于威慑（账号实名 →
可追责）与取证（定位泄露者 → 法律行动 + 封号）。

## 二、文本水印技术全景（五类方案）

### 2.1 方案 W1：零宽字符水印 ⭐ 简单、性价比最高

**原理**：在文本中插入不可见的 Unicode 零宽字符（U+200B 零宽空格、U+200C 零宽不连字、
U+200D 零宽连字、U+FEFF 零宽不换行空格），用它们的组合序列编码二进制信息。

```
编码示例（1 个零宽字符 = 1 bit）：
  用户ID = 8848 → 二进制 → 10001010010000
  → 按"每个'，'后藏 1 bit"的方式嵌入：

  原文：夜色渐深，他推开门，屋内无人。
  藏水：夜色渐深​，他推开门‌，屋内无人‌。
         (看起来一模一样，实际"深"后多了 U+200B)
```

| 特性 | 表现 |
|------|------|
| 对阅读体验影响 | 零（字符不可见，不占宽度） |
| 抗复制粘贴 | ✅ 强 —— 复制文本时零宽字符跟随 |
| 抗格式转换 | ✅ 强（TXT/Word/HTML 保留） |
| 抗重排/换行 | ⚠️ 中 —— 部分编辑器/平台会过滤非常规字符 |
| 抗盗版商清洗 | ❌ —— 已知方案，正则一键清除（盗版商普遍会做） |
| 实现成本 | 极低，纯字符串处理，任何语言可做 |

**增强**：为对抗"正则清洗"，把水印 bit 同时藏进**多种不可见载体**混合嵌入：
零宽字符 + 中文标点变体 + 全角/半角空格混用。清洗者需枚举所有载体，大幅提高清洗成本。

### 2.2 方案 W2：同义词替换水印 ⭐ 鲁棒性主力

**原理**：为每个需要编码 bit 的"锚点"，在两（或多）个语义等价的表达中切换。
中文天然适合（同义、近义、语序弹性）：

```
锚点组示例（每处可编码 1 bit）：
  "他快步走过去"  ⇄  "他疾步走过去"    → bit 0/1
  "月亮升了起来"  ⇄  "月亮爬了上来"    → bit 0/1
  "三天后"        ⇄  "三天之后"        → bit 0/1
  "的地得"互换、语序微调、四字格展开压缩 ...

编码：用户ID(32 bit) 分散到一章的 32+ 个锚点上（一章 2000-4000 字，
   可选锚点通常 >100 处，冗余编码 2-3 倍提高存活率）
```

| 特性 | 表现 |
|------|------|
| 对阅读体验影响 | 极低（语义不变） |
| 抗清洗 | ✅✅ **强 —— 字符级清洗完全无效**（每处都是"正常汉字"） |
| 抗重排版 | ✅ 强 |
| 抗 OCR | ✅ 强（文字本身被正常识别，替换关系保留） |
| 实现难点 | ① 需要高质量中文同义/等价表达库 ② 需要上下文消歧避免"替换后不通顺" |

**消歧方案**（难点解法）：
1. 构建人工审核过的**等价对库**（初期 500-2000 对，覆盖高频表达），保证"零风险替换"
2. LLM 辅助生成候选替换对，人工抽检入库（扩展到数万对）
3. **红线约束**：对话引号内、人名、地名、数字、诗赋韵文一律不替换

### 2.3 方案 W3：句式/标点微扰水印

利用中文书写的合法自由度：
- 引号风格："" vs 「」（每章混用比例编码）
- 省略号：…… vs ...
- 句末语气词冗余："吧""呢" 的取舍
- 被动/主动句改写（"门被他推开" ⇄ "他推开门"）

特点：抗清洗中等，常与 W2 混合使用增加鲁棒性。需要句法分析，实现较重，**二期再做**。

### 2.4 方案 W4：渲染层指纹（抗截图/OCR 杀手锏）

**原理**：不做文本替换，而在**字形渲染**上做文章 —— 每个用户加载的 webfont 中，
随机挑选 N 个高频字做极微小变形（基线偏移 0.01em、字宽 ±0.5%、笔画粗细微调），
变形模式由用户 ID 决定。截图后通过字形比对还原用户 ID。

```
┌────────────────────────────────────────────┐
│  生成管线（每用户首次阅读 VIP 章时触发）        │
│                                            │
│  字体模板(千字形库) + 用户ID → PRNG种子       │
│       → 挑选 30 个高频字微扰                  │
│       → 动态生成子集 woff2 (仅含用到字形)      │
│       → CDN 缓存 per-user 字体 URL           │
└────────────────────────────────────────────┘
检测：盗版截图 → 提取若干"变形字" → 与模板库比对 → 定位用户
```

- 抗 OCR：✅ OCR 识别出的文本不变，但**截图原图**保留字形痕迹
- 成本：字体动态生成服务（Python fontTools 可做）、每用户字体缓存管理
- 注意：这是**渲染层反爬（字体混淆）与水印的合体** —— 一箭双雕，也是主流平台没做过的深水区

### 2.5 方案 W5：KGW 统计水印（仅用于平台 AI 工具产生的内容）

绿红列表(Green-Red list)统计水印：文本生成时控制 token 选择分布，使统计检验可检测。
适用场景：平台官方工具（AI 起名/润色/摘要）产生的内容标注。
**与作者原创内容无关，仅做合规标签用。**

## 三、段落级指纹体系（溯源的关键结构）

水印解决"哪个用户"，段落指纹解决"哪一章哪一段、是否被篡改"：

```
┌─────────────────────────────────────────────────────┐
│  章节发布时（作者点击"发布"）                          │
│                                                     │
│  原文 ──▶ 规范化(去空白/统一标点) ──▶ 按段切分         │
│     ├─ 每段 → SHA-256 → para_hash[]                  │
│     └─ 全章 → Merkle 树 → root_hash                  │
│          ├─ 存本地 paragraph_fingerprints 表          │
│          └─ root_hash + 元数据 → 上链（见文档04）      │
│                                                     │
│  盗版发现时                                          │
│     盗版文本 ──▶ 同样规范化/切分 ──▶ 逐段比对          │
│     ├─ 匹配段数/总段数 = 相似度（对抗"改几个字"）       │
│     ├─ 相似度 > 70% 即认定实质性相似                   │
│     └─ 提取水印 → 定位泄露账号                        │
└─────────────────────────────────────────────────────┘
```

**为什么用段落级而不是整章哈希**：盗版商常改开头结尾、加广告、调换语序来"去重"。
段落指纹让"部分匹配"也能确权 —— 这正是维权时举证的核心（实质性相似认定）。

**Merkle 树的作用**：链上只存一个 root（省钱），但任意单段的哈希都能验证其归属，
不需要把整章哈希全部上链。

## 四、水印工程架构与数据模型

### 4.1 数据模型（概念）

```
watermark_seeds (水印种子表)
├─ user_id, book_id, chapter_id
├─ seed (随机种子，用于生成该用户的零宽+同义词方案)
├─ payload (编码的用户标识，含冗余校验位 ECC)
└─ created_at, engine_version

paragraph_fingerprints (段落指纹表)
├─ chapter_id, para_no, para_hash
└─ (可选) merkle_path 验证路径

watermark_audits (盗版溯源记录)
├─ evidence_id, found_url, matched_paragraph_count
├─ extracted_user_id (溯源结果), confidence
└─ similarity_score, chain_cert_id (对应的链上证书)
```

### 4.2 生成流水线

```
章节发布
  │
  ▼
[异步任务1] 指纹与存证         [异步任务2] 水印库预备
  · 规范化+分段                 · 锚点识别（同义对匹配）
  · Merkle root                 · 可替换点标记
  · 上链(root+meta)             · 生成"水印方案模板" per chapter
  │
  ▼
用户请求阅读 (VIP 章)
  │
  ▼
按 user_id + chapter_id 查/建 watermark_seed
  │
  ▼
[实时渲染] W1 零宽嵌入（纯字符串处理，PHP/Go 即可）
        + W2 同义词替换（查预计算结果，无实时 NLP 开销）
        + W4 用户字体 URL（缓存命中则直出）
  │
  ▼
响应（注意：水印版内容 per-user，不走公共 CDN；
     免费章节不打水印，继续走 CDN 加速）
```

关键工程点：
1. **W2 的替换在发布时预计算**（离线完成），阅读时只是查表渲染，避免运行时 NLP 开销
2. 水印方案 per (user, chapter) **确定**（同用户每次读相同结果），否则用户自己比对两次抓包即可破解
3. 免费章节与 VIP 章节走不同的缓存/渲染路径

### 4.3 检测（溯源）流程

```
盗版监测爬虫(定时 / 作者手动提交盗版链接)
  │
  ▼
规范化盗版文本 → 段落指纹比对（命中本书/本章？相似度？）
  │
  ├─ 命中 → 提取 W1 零宽序列（若盗版商没清洗）
  │         ├─ 成功 → 得到 user_id → 封号/追责
  │         └─ 失败(被清洗) → 提取 W2 同义词分布
  │              ├─ 统计锚点 bit 序列 → ECC 纠错恢复 → user_id
  │              └─ 置信度 < 阈值 → 人工抽样锚点确认
  │
  └─ 同时：生成取证包（原文哈希 + 链上证书 + 盗版快照 + TSA 时间戳）
        → 输出：平台内封号 / 提供给作者一键下载维权材料
```

## 五、实施分期与成本

| 阶段 | 内容 | 成本 | 效果 |
|------|------|------|------|
| 一期 | W1 零宽水印 + 段落指纹 + 本地哈希库 | 1-2 周开发 | 防小白复制，可溯源"懒惰盗版商" |
| 二期 | W2 同义替换（等价对库 2000 对起步）+ TSA 存证 | 4-6 周，含词库建设 | 溯源能力覆盖 90%+ 常见盗版文本 |
| 三期 | W4 渲染层指纹 + 字体混淆反爬一体化 | 6-8 周 + 字体工程 | 抗截图/OCR，反爬与水印合体 |
| 四期 | 盗版监测爬虫 + 溯源自动化 + 取证包自动生成 | 持续运营成本 | 完整维权闭环 |

**风险提示**：
- W2 依赖等价对库质量，早期覆盖率低 → 只对"付费章节"启用，且先灰度观察读者反馈
- W4 需评估 webfont 加载对移动端阅读性能的影响（子集化控制在 100KB 内）
- 所有水印必须通过"作者预览"—— 作者看到的最终渲染就是读者版本（避免"作者不知道自己的书被改了"的信任危机），作者协议中明确披露水印机制

## 六、与竞品的差异化定位

```
起点/番茄：字体混淆反爬（防爬，但对"已订阅用户复制"无能为力）
本平台  ：per-user 盲水印（专治内部泄露，付费内容的真正泄露源）
         + 段落指纹 + 链上确权（维权可用的证据链）
         + 溯源结果反哺作者（透明度）
```
"你不但能看到是谁泄露了你的书，还能拿到可以直接递给律师的证据包" —— 这是
对作者最有说服力的卖点，竞品没有对等能力。

# 04 · 区块链存证与上链方案（深度版）

> 核心问题：**是否上蚂蚁链？还是别的？**
> 结论先行：**不自建链；主体走腾讯至信链 API（1 元/条）；关键证据补 TSA 可信时间戳；
> 蚂蚁链作为规模期的备选/双链冗余；只上哈希永不上原文。**

---

## 一、先想清楚：上链到底为了什么

```
┌─────────────────────────────────────────────────────┐
│ 上链解决的三个独立问题                                 │
├─────────────┬──────────────────────┬────────────────┤
│ ① 确权      │ 证明"我在时间T发布了     │ 章节 Merkle root │
│ (存证)      │ 内容哈希H的版本"        │ + 元数据上链     │
├─────────────┼──────────────────────┼────────────────┤
│ ② 交易可信   │ 证明"作者收益按规则     │ 分账流水 Merkle  │
│ (账本)      │ 计算，没被平台篡改"      │ root 定期上链    │
├─────────────┼──────────────────────┼────────────────┤
│ ③ 取证      │ 发现盗版时，能出一份    │ 链上证书 + TSA   │
│ (维权)      │ 法院认可的电子证据      │ 时间戳取证包     │
└─────────────┴──────────────────────┴────────────────┘
```

**关键认知**：
1. 上链 ≠ 版权登记。链上存证证明"你持有该内容且时间可查"，是维权时的**初步证据**；
   官方版权登记（中国版权保护中心 DCI）效力更强但周期长费用高 —— 平台两者都可对接。
2. 区块链在司法上已被采信：杭州/北京/广州互联网法院自 2018 年起采信链上存证，
   最高法《关于互联网法院审理案件若干问题的规定》第 11 条明确认可。
3. **原文永不上链**：a) 内容合规风险（审核责任）；b) 链上数据公开或半公开；
   c) 成本。**只上 SHA-256 哈希 + 元数据**，零泄露、零合规风险。

## 二、候选方案全面对比（2026 实况调研）

### 2.1 总览

| 方案 | 性质 | 计费（实测） | 司法采信 | 接入难度 | 适合 |
|------|------|-------------|---------|---------|------|
| **腾讯至信链** | 开放联盟链(服务化) | **1 元/条(预付) / 1.5 元/条(后付)** | 强：法院/公证处合作，可出电子存证证书 | 低：腾讯云 API 直连 | **主体方案** |
| **蚂蚁链 BaaS** | 联盟链服务 | 按天计费（服务包，约数百元/天起），开放联盟链按量另算 | 强：杭州互联网法院判例多 | 中：BaaS 平台配置 + SDK | 备选/双链 |
| **BSN 开放联盟链** | 国家级基础设施 | 几千元/年 + 按量燃料费 | 中：取决于所选底层链 | 中 | 预算敏感的批量存证 |
| **自建 FISCO BCOS / 长安链** | 私有/自管联盟链 | 3-4 节点云服务器约 **2-5 万/年** + 人力 | 弱（自证存证，需另接司法/公证联盟才有强效力） | 高：需区块链工程师 | 有技术团队的大型机构 |
| **TSA 可信时间戳** | 中心化权威时间戳（非链） | 按次计费（个位数元/条，量大可谈） | 强：判例极多，联合信任时间戳服务中心（国家授时中心授时） | 极低：API | **取证包必配** |
| 版权登记 DCI | 官方登记 | 数十至数百元/件，周期数天-数周 | 最强 | 线下流程 | 高价值作品增值服务 |

### 2.2 各家深挖

**腾讯至信链**（主体推荐）
- 腾讯联合生态伙伴运营，有"版权存证"专项产品（腾讯云产品编号 1505）
- 计费清晰：预付费 1 元/条，后付费 1.5 元/条（一条 = 一次存证）
- 有完整出证链路：存证 → 电子证书 → 至信链可信存证平台可查验
- 生态协同：微信生态（公众号侵权场景）取证顺畅
- 风险：单一供应商依赖 → 用"哈希本地留底 + 双链可选"对冲

**蚂蚁链 BaaS**（备选）
- 阿里云 BaaS 平台按服务包（元/天）计费，另有"数字权证合约服务"等衍生计费
- 杭州互联网法院判例丰富（蚂蚁链 IP 平台），司法认可度高
- 对小平台偏贵：按天计费是**固定成本**（不存证也扣费），适合日存证量大的场景
- 结论：日存证数千条以上才有经济性；起步期不选，规模期做第二链（双链冗余提高公信力）

**BSN 开放联盟链**（预算敏感选项）
- 国家信息中心牵头，接入费低（约几千元/年），兼容 FISCO BCOS/长安链等多框架
- 人民币计价燃料机制，批量存证边际成本低
- 弱点：司法采信要看具体底层链与背书主体，"BSN"本身不是法院认可的"证据品牌"
  → 涉诉时主要证据仍需 TSA/至信链补强

**自建联盟链**（明确不推荐）
- 2-5 万/年基础设施 + 区块链工程师（难招且贵）
- 最大死穴：**自建链存证在法庭上属于"自证"** —— 法官会问"这个链谁运营？谁能改数据？"
  除非接入有法院背书的司法联盟链，否则公信力不如第三方
- 结论：只有想把"链"本身做成卖点（数字藏品/权证）才考虑，MVP 阶段绝不碰

**TSA 可信时间戳**（必配，非链的补充）
- 联合信任时间戳服务中心（tsa.cn），国家授时中心授时，司法采信最成熟
- 有 AIGC 创作过程存证专项；电子取证平台支持网页取证/录屏取证
- 定位：至信链管"确权"，TSA 管"取证 + 权威时间"，双保险

### 2.3 推荐组合（分层）

```
┌──────────────────────────────────────────────────┐
│ 第 1 层（默认）：章节确权                           │
│   至信链 API，付费书逐条 1 元                        │
│ 第 2 层（增强）：关键作品/合同/分账月结               │
│   至信链 + TSA 可信时间戳 双存证                    │
│ 第 3 层（规模期）：双链冗余                          │
│   蚂蚁链作为第二存证通道，作者端可查看双链证明        │
│ 第 4 层（服务层）：高价值作品                        │
│   引导/代办 DCI 版权登记（收费增值服务）              │
└──────────────────────────────────────────────────┘
```

## 三、上链内容设计

### 3.1 存证载荷（payload）

```json
{
  "type": "chapter_evidence",
  "book_id": "bk_10294",
  "chapter_id": "ch_883721",
  "author_id": "au_1155",
  "chapter_title_hash": "SHA256:9f2c...",
  "content_merkle_root": "SHA256:e41b...(段落指纹Merkle根)",
  "word_count": 3124,
  "version": 3,
  "license": "CC_BY_NC_ND_40",
  "published_at": "2026-09-28T10:00:00+08:00",
  "platform": "ruoshu",
  "prev_chapter_root": "SHA256:77aa...(链式，防抽章篡改)"
}
```
上链的是这段 JSON 的哈希（或 JSON 本身，视链的存储模型），**不含任何正文**。

设计要点：
- **链式哈希**：每章存证引用前一章的 root —— 整本书形成不可断裂的链条，
  盗版商无法声称"只抄了其中免费章节"
- **版本号**：修改后重新存证（新版本新存证），保留完整创作时间线证据
- **license 字段**：授权选择也固化在存证里（与文档 03 呼应）

### 3.2 分账账本上链（不同节奏）

```
逐笔流水 → 本地 MySQL（唯一真源）
    │
    ├─ 每小时：该小时所有流水 → Merkle 树 → root 上链（至信链 1 条/小时）
    │   成本：24 条/天 ≈ 720 元/月 → 优化为每 4 小时 1 条 ≈ 180 元/月
    └─ 每月：月度对账单 root + TSA 时间戳 → 生成作者对账 PDF

核对：作者任一笔流水 → 提供 merkle path → 与链上 root 比对 → 证明未被篡改
```

### 3.3 分级存证策略（成本控制核心）

```
章节类型           存证策略                      成本
──────────────────────────────────────────────────────
免费章节           本地哈希库 + 每日 Merkle root    ≈1 元/天
                   打包上链（一天 1 条）
付费/VIP 章节      逐章上链                       1 元/章
签约书全本         逐章上链 + TSA 双存证           ~3 元/章
涉诉取证           TSA 网页取证 + 公证引导          按次
──────────────────────────────────────────────────────
成本测算：
· 起步期（日更 100 章，付费 20 章）≈ 25 元/天 ≈ 750 元/月 —— 可承受
· 规模期（日更 2000 章，付费 300 章）≈ 330 元/天 ≈ 1 万元/月 → 谈阶梯折扣
```

## 四、技术接入架构

```
                    ┌───────────────────────┐
                    │  存证调度服务(队列消费者)  │
                    │  · 幂等/重试/对账         │
                    └──────┬────────────────┘
                           │
        ┌──────────────────┼──────────────────┐
        ▼                  ▼                  ▼
┌───────────────┐  ┌───────────────┐  ┌──────────────┐
│ 至信链 API     │  │ TSA API       │  │ 本地存证库     │
│ (SDK/REST)    │  │ (REST)        │  │ MySQL+OSS     │
│ → tx_id       │  │ → tsa_cert    │  │ 全量哈希留底    │
└───────────────┘  └───────────────┘  └──────────────┘

可靠性设计：
1. 上链是异步任务，发布流程不阻塞（先发布，后台 30 秒内完成存证）
2. 每笔存证落库：pending → submitted → confirmed；失败重试进死信队列
3. 本地哈希库永远保留（链服务挂/涨价/跑路，随时切新链补存）
4. tx_id 回写 chapters 表；作品页展示"已存证"徽章 + 证书编号
```

**给作者端的呈现**（产品化重点）：
- 作品页：「本作品已上链存证 · 存证号 xxx · 点击验证」
- 验证页：输入任意一段原文 → 现场算 SHA-256 → 展示与链上记录匹配（可视化确权演示）
- 取证包下载：链上证书 + TSA 证书 + 原文哈希清单 + 盗版比对报告（PDF）→ 可直接给律师

## 五、风险与合规清单

| 风险 | 应对 |
|------|------|
| 链服务商停服/涨价 | 哈希本地留底 + 存证适配层（换链=换驱动）+ 双链冗余 |
| 存证被法院不采信 | 主用至信链/TSA 等有判例的服务；高价值作品引导 DCI 登记 |
| 作者误存侵权内容 | 存证只证明"提交时间"不证明"原创性" —— 抄袭检测在上传时独立做 |
| 链上元数据泄露内容 | 载荷只含哈希与数字，章节标题也哈希化 |
| 成本失控 | 分级策略 + 每日账单告警 + 存证量与营收挂钩（付费章节才逐章存证） |

## 六、最终结论

```
Q: 是否上蚂蚁链？
A: 起步期不上。蚂蚁链 BaaS 按天计费是固定成本，对日存证量小的平台不划算。
   主力选至信链（1元/条按量计费 + 接入简单 + 出证链路完整）。
   规模期（日存证数千条、或要做数字藏品/权证）再引入蚂蚁链做双链冗余，
   同时提高对外公信力（两家的司法判例都很多）。

Q: 还要不要别的？
A: 要。TSA 可信时间戳是"司法确认感"最高的便宜补强，取证包必配；
   自建链永远不做（自证无效+成本高+无司法品牌）。
```

## 七、至信链推荐的保留意见与对冲设计

**是的，起步阶段推荐它做主力 —— 但不是信仰选择，是"当前约束下的最优解"。**

### 7.1 推荐它的三条硬理由

```
                    蚂蚁链 BaaS          至信链              TSA 时间戳
计费模式            按天包干(固定成本)     按条计费(可变成本)    按次计费
起步期日存证~50条    数百元/天 ❌         ~50元/天 ✅          按需
接入方式            BaaS 控制台+SDK       腾讯云标准 API       标准 API
出证能力            有                    有(电子存证证书)     有(认证证书)
司法判例            多(杭州)              多(深圳前海等)       最多、最成熟
生态契合            阿里系                微信生态/腾讯云       中立机构
```

三个决定性理由：
1. **计费模型匹配阶段**：按条计费 = "零存证零成本"，固定成本变可变成本，对未验证营收的平台是生死攸关
2. **它首先是"腾讯云产品"**：有产品文档、SLA、工单系统、API 稳定性是商业承诺，不是某个区块链团队的爱好项目
3. **出证闭环现成**：存证 → 电子证书 → 查验页，作者端产品化时不需要自己造

### 7.2 必须说清楚的保留意见

**① 它本质仍是"腾讯主导的联盟链"** —— 开放是相对的。押注的是腾讯的持续运营意愿
和司法合作的持续性。对冲方式：**本地全量哈希留底 + 存证适配层（换链=换驱动）**。
哈希在你自己手里，理论上任何时候可以换一条链"补存"（补存证明力弱一些，但主权在作者侧）。

**② 存证 ≠ 版权登记 ≠ 胜诉**。链上证书在诉讼中是"初步证据"，法官仍可能要求
比对原文创作过程。所以 TSA（创作过程时间线）和未来引导 DCI 登记（法定登记效力）
要分层存在 —— **单一依赖任何一条链都是错误姿势**。

**③ 反向风险**：至信链也存过侵权内容（别人抄你的书然后抢先存证）。技术上无法从
存证层防，防御手段是**发布时间戳 + 段落指纹的密度**（你日更连载、逐章存证，
抄袭者一次性存证，时间线上你赢）—— 这又回到文档 02 的设计，三者是咬合的。

### 7.3 三层对冲设计（写进工程实现）

```text
┌─────────────────────────────────────────────────────┐
│ 第 1 道对冲：本地全量哈希 + 适配层抽象                    │
│   · 哈希和元数据 100% 存在自己 OSS（绝不依赖链）          │
│   · 存证服务以 driver 模式设计：tochain(d) → switch(d) │
│   · 切换新链的成本 = 写一个新 driver                    │
├─────────────────────────────────────────────────────┤
│ 第 2 道对冲：双链冗余（规模期启用）                       │
│   · 至信链（主）+ 蚂蚁链/BSN（备）                       │
│   · 作者端展示"双链证明"页，对外公信力翻倍               │
├─────────────────────────────────────────────────────┤
│ 第 3 道对冲：法律证据层级                                 │
│   · 至信链 = 商业存证（日常确权）                        │
│   · TSA = 时间权威 + 取证包（涉诉必配）                  │
│   · DCI = 法定登记（高价值作品付费代办）                  │
│   · 合同电子签 = 作者-平台关系确权                       │
└─────────────────────────────────────────────────────┘
```

### 7.4 最终链策略（一句话）

```
起步期：  至信链(逐章确权) + TSA(取证包)          —— 月成本 <1000 元
规模期：  + 蚂蚁链做双链冗余(对外公信力翻倍)      —— 日存证>3000 时
高价值：  + 引导 DCI 官方登记(收费增值服务)        —— 个案
永远不：  自建链(自证无效)、原文上链(合规红线)
```
